# Brief: Internet Accountability Compass, v3 build

## Context

Client: European University Institute (EUI), GIFI Project
(https://globalgovernanceprogramme.eui.eu/gifi/).

Live site (v2, currently deployed; v3 is what we are building): Observable Framework 1.13.x + D3 + Observable Plot, deployed to
GitHub Pages from `main` via .github/workflows/deploy.yml
(base path `/internet-accountability-compass/`). It is embedded as an iframe on
a WordPress page I don't control:
https://globalgovernanceprogramme.eui.eu/gifi/internet-accountability-compass/

The embed code is fixed and cannot be changed by me or the client's page:
`<iframe width="100%" height="100%" frameborder="0"
src="https://cdtrich.github.io/internet-accountability-compass/"></iframe>`
No sandbox/allow attributes, no resize listener, no parent-page access.

Data comes from R loaders in src/data/ reading the Excel index (currently
Internet-Accountability-Index-V3.0.xlsx; V6 before the update).
~190 country pages (194 at last regeneration) are generated by
src/1generateCountryPages.r from src/1countryPageTemplate.md. Components live in
src/components/ (~21 modules).

No brand guidelines and no fixed deadline for v3.

Durable traps and tooling notes: DEV_NOTES.md (imported by CLAUDE.md).

## Ground rules

- NEVER push to or merge into `main`, and never trigger the live deploy.
  All work happens on `dev`/feature branches and in the staging repo.
- No admin rights on this machine. Use portable or user-level installs only.
  If something needs admin, stop and tell me.
- Make small, reviewable commits. Before any destructive or large-scale change
  (deleting files, regenerating all country pages, changing the framework,
  touching .github/workflows/, overwriting data), state the risk and a rollback
  step, then wait for my OK.
- Keep a running log in CHANGELOG_V3.md: what changed, why, how to verify.
- Report findings with evidence (numbers, file paths), not impressions.
  Label estimates as estimates.
- The site runs inside a cross-origin iframe with a fixed embed (see Context).
  Nothing may require a change on the WordPress side. The production URL
  (github.io user, repo name, base path) must NOT change, or the embed breaks.
  Do not rename, move or transfer the live repo.
- The iframe is height="100%", so the site fills whatever height the parent
  container gives it and must handle its own scrolling. Treat 100vh/100dvh as
  the iframe height, not the browser window.
- R stays the data layer. Loaders must be reproducible (same input, same
  output). Flag anything that would break the generated country pages.

## Phase 4: Performance

Targets (defaults, adjust after the baseline): LCP < 2.5 s on mobile, no long
animation tasks, CLS near 0.

Candidates to check: data payload size (trim columns, split per-country data,
compress), lazy-load charts below the fold, import D3 modules selectively
instead of the full bundle, cache and fingerprint assets, image/GIF weight,
animation cost (prefer CSS transforms/opacity, requestAnimationFrame, avoid
re-rendering whole SVGs, respect prefers-reduced-motion).

Iframe: measure inside the frame as well as standalone. Since the embed cannot
change, do not add height-reporting to the parent. Instead make the layout
robust to any container height: no clipped content, no double scrollbars, no
reliance on window-height units that misbehave in a frame, and sensible
behaviour in very short or narrow containers.

Re-measure against the Phase 0 baseline after each change and log the delta.
